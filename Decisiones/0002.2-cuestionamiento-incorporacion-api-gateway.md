# 0002.2 - Cuestionamiento crítico de la incorporación del API Gateway

- **Estado:** Revisión realizada.
- **Fecha:** 2026-11-10
- **Arquitectos Cognitivos (ASC):** Sergio González y Sara Guillén.
- **Arquitectos Senior (ASS):** Antonio Machuca y Enrique Aldama.
- **Decisión revisada:** ADR-0002 - Incorporación de API Gateway.

## Cuestionamiento crítico

Sergio González (ASC) cuestionó si incorporar un API Gateway únicamente para distinguir entre PC y Tablet suponía complicar demasiado la arquitectura del periódico digital.

La duda principal era si las ventajas de utilizar este componente justificaban la complejidad que daba.

## Respuesta de los arquitectos senior

Antonio Machuca y Enrique Aldama (ASS), junto con Sara Guillen (ASC), explicaron que el profesor Rafael Capilla había orientado al equipo hacia la utilización de un API Gateway para separar los dispositivos de la lógica de negocio del backend.

Además, para evitar añadir complejidad innecesaria se acordó limitar las responsabilidades del API Gateway a dos funciones:

1. Identificar si el cliente accede desde un PC o una Tablet.
2. Redirigir las peticiones HTTP/REST al controlador correspondiente del backend.

## Conclusión de la revisión

Después de valorar la observaciones e inconvenientes se mantiene la propuesta de incorporar el API Gateway, pero limitando sus funciones para que solamente sean las necesarias para resolver el RF1.

Por todo ello, se busca evitar que el componente tenga más responsabilidades de las necesarias y mantener la separación entre la identificación de dispositivos y la lógica de negocio.

La decisión queda formalizada y desarrollada en la decisión [ADR-0002.3](0002.3-reafirmacion-incorporacion-api-gateway.md).
